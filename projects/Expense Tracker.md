# Expense Tracker

## 📌 Задача

CLI-трекер расходов за день. Не связан со старыми проектами ([[Buy Manager]], [[Contact Book]] — оба намеренно припаркованы) — это отдельный, более приближенный к реальному приложению кейс.

Функционал:
- **Добавить расход** — категория (строка) + сумма (число)
- **Показать сумму по категориям** — например, "еда: 1200, транспорт: 300"
- **Показать все расходы** — читаемый список
- **Выйти**

## ⚙️ Архитектурные требования

- Данные — словарь вида `{"еда": [200, 500, 100], "транспорт": [300]}` (категория → список сумм). Это осознанно сложнее, чем плоский список — заставляет реально работать со словарём, а не подглядывать в [[Contact Book]]
- Каждый пункт меню — отдельная функция, меню в `while True` с `break` (паттерн из [[ATM]] v3)
- Данные передаются параметром и возвращаются через `return`, без `global`
- **Пока НЕ использовать `try/except`** — даже если знаешь конструкцию. Это намеренное ограничение, см. ниже

**Ревью (16.07):**
- `add_expense` — правильно понял mutable vs immutable: меняет словарь по ссылке, без `return`, в отличие от ATM, где `balance` (int) требовал `return`.
- Прошёл через 3 итерации фикса retry-логики для суммы: сначала `continue` (откатывал слишком далеко, заново спрашивал категорию), потом `break` без своего `while True` (ломал программу двумя разными способами — пропускал `add_expense` при успехе, `NameError` при ошибке), в итоге — верный вложенный `while True` вокруг `try/except` именно для суммы.
- Основной вынесенный урок: `break`/`continue` всегда действуют на **ближайший** объемлющий цикл — если своего цикла нет рядом с местом, где нужен `break`, он сработает не на том уровне.
