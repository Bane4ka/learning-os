# Sets (множества)

> [!info] Что это
> Set — неупорядоченная коллекция **уникальных** элементов. Дубликаты автоматически отбрасываются, порядок не гарантирован. Реализован через хэш-таблицу — тот же механизм, что лежит в основе `dict` (ключи словаря — по сути тоже set).
>
> ```python
> players = set()
> players.add("Ваня")
> players.add("Ваня")   # ничего не изменится, дубликат не добавится
> print(players)          # {'Ваня'}
> ```

---

## Синтаксис — где легко ошибиться

```python
empty_set = set()        # пустой set — только так
empty_dict = {}            # это словарь, НЕ set!

numbers = {1, 2, 3}         # set с элементами — фигурные скобки, без ключ:значение
from_list = set([1, 2, 2, 3])  # {1, 2, 3} — создание set из списка сразу убирает дубликаты
```

> [!danger] `{}` — это не пустой set
> `type({})` → `dict`. Синтаксис `{}` зарезервирован под словарь ещё до того, как в язык добавили set — это историческая несостыковка, которую просто нужно запомнить.

---

## Обязательное требование: элементы set должны быть хэшируемыми

```python
valid = {1, "a", (1, 2)}     # работает — числа, строки, кортежи хэшируемы
invalid = {1, [1, 2]}         # TypeError: unhashable type: 'list'
```

Это та же причина, по которой список нельзя использовать как ключ словаря (см. [[014 Tuples]]) — **изменяемые** объекты (list, dict, set) не хэшируются, потому что их содержимое может измениться после добавления, а хэш обязан оставаться постоянным всё время жизни объекта в коллекции.

## Основные операции

```python
seen = {"a", "b"}
seen.add("c")             # добавить один элемент → {'a', 'b', 'c'}
seen.update(["d", "e"])     # добавить сразу несколько → {'a','b','c','d','e'}
seen.remove("a")             # удалить — упадёт с KeyError, если элемента нет
seen.discard("z")             # удалить — НЕ упадёт, если элемента нет
"a" in seen                    # проверка наличия — O(1)
len(seen)                        # количество элементов
seen.pop()                        # удаляет и возвращает произвольный элемент (порядок не гарантирован!)
```

> [!tip] `.discard()` vs `.remove()`
> Если не уверен, есть ли элемент в set — используй `.discard()`. Если уверен и хочешь узнать об ошибке, если элемента вдруг не оказалось — `.remove()`. Тот же принцип выбора, что и между `dict[key]` и `dict.get(key)` из [[012 Dictionaries]].

## Операции над множествами — теория множеств на практике

```python
a = {1, 2, 3, 4}
b = {3, 4, 5, 6}

a | b     # объединение (union): {1,2,3,4,5,6} — всё, что есть хотя бы в одном
a & b      # пересечение (intersection): {3,4} — что есть в обоих
a - b       # разность (difference): {1,2} — что есть в a, но нет в b
a ^ b        # симметрическая разность: {1,2,5,6} — что есть ровно в одном из двух

a.issubset(b)     # является ли a подмножеством b
a.issuperset(b)    # является ли a надмножеством b
```

Практический пример — сравнение двух групп пользователей:
```python
active_users = {"anna", "ivan", "petr"}
premium_users = {"ivan", "olga"}

active_users & premium_users    # {'ivan'} — активные премиум-пользователи
active_users - premium_users     # {'anna', 'petr'} — активные, но не премиум
```

## Зачем это нужно, если можно проверять `x in list`

> [!tip] Правило
> `x in list` перебирает список элемент за элементом — `O(n)`, время растёт линейно с размером списка. `x in set` работает через хэш и не замедляется с ростом коллекции — `O(1)` в среднем (см. [[016 Big O]]). На практике это значит: если тебе нужна проверка "уже видели этот элемент?" много раз подряд в цикле — `set` может быть разницей между секундами и часами на больших данных.

Пример прямого сравнения:
```python
# O(n²) — для каждого элемента проверка в списке — O(n) внутри O(n) цикла
seen_list = []
for item in big_data:
    if item not in seen_list:
        seen_list.append(item)

# O(n) — проверка в set — O(1) внутри O(n) цикла
seen_set = set()
for item in big_data:
    if item not in seen_set:
        seen_set.add(item)
```

## Frozenset — неизменяемая версия set

```python
frozen = frozenset([1, 2, 3])
frozen.add(4)   # AttributeError — frozenset не поддерживает изменение
```

Используется редко, но встречается: нужен, когда сам set должен быть элементом **другого** set или ключом словаря (обычный `set`, как и `list`, не хэшируется, а `frozenset` — хэшируется, потому что неизменяем). Не углубляйся в это сейчас, просто знай, что такое существует.

## Частые ошибки

> [!warning] `{}` — это не пустой set
> Разобрано выше — самая частая ошибка новичков с set.

> [!danger] `.remove()` на несуществующем элементе
> `seen.remove("x")`, если `"x"` там нет → `KeyError: 'x'`. Используй `.discard("x")`, если не уверен, что элемент точно есть.

> [!danger] Ожидать порядок в set
> ```python
> s = {3, 1, 2}
> print(s)   # порядок вывода НЕ гарантирован, может быть {1, 2, 3} или другой
> ```
> Если порядок важен — используй список (отсортированный при необходимости), не set.
