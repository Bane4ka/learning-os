# *args и **kwargs

> [!info] Что это
> Способ написать функцию, которая принимает **заранее неизвестное количество** аргументов — позиционных (`*args`) или именованных (`**kwargs`). Ты уже писал функции с фиксированным числом параметров (`def add_expense(expenses, category, amount)`) — здесь речь о случаях, когда число аргументов заранее неизвестно или может меняться.

---

## `*args` — произвольное число позиционных аргументов

```python
def total(*args):
    print(args)          # это ВСЕГДА tuple, даже если передан один аргумент
    return sum(args)

total(1, 2, 3)      # args = (1, 2, 3) → 6
total(5)             # args = (5,) → 5
total()               # args = () → 0
```

Звёздочка `*` перед именем параметра говорит Python: "собери все переданные позиционные аргументы, которые не уместились в обычные параметры, в один tuple с этим именем". Имя `args` — просто соглашение (можно назвать иначе), важна именно `*`, а не конкретное слово.

### Зачем это нужно, если можно передать список

```python
def total_v2(numbers_list):
    return sum(numbers_list)

total_v2([1, 2, 3])     # приходится оборачивать в список самому
total(1, 2, 3)            # а тут можно просто перечислить через запятую
```

Разница не критичная для `sum`, но становится важной, когда пишешь функцию, похожую на встроенные — `print(1, 2, 3)` работает именно потому что `print` определён с `*args` внутри.

## `**kwargs` — произвольное число именованных аргументов

```python
def describe(**kwargs):
    print(kwargs)          # это ВСЕГДА dict
    for key, value in kwargs.items():
        print(f"{key}: {value}")

describe(name="Ваня", age=25, city="Москва")
# kwargs = {'name': 'Ваня', 'age': 25, 'city': 'Москва'}
```

Двойная звёздочка `**` собирает все переданные именованные аргументы (`ключ=значение`), которые не уместились в обычные параметры, в один `dict`. Это прямая связь с [[012 Dictionaries]] — работаешь с `kwargs` внутри функции ровно так же, как с любым словарём (`.items()`, `.get()`, `key in kwargs`).

---

## Порядок параметров в определении функции — строгие правила

```python
def func(a, b, *args, c, d=10, **kwargs):
    ...
```

Порядок фиксирован и не может быть произвольным:

1. Обычные позиционные (`a, b`)
2. `*args`
3. Именованные, обязательные только по имени (`c`) — после `*args` любой параметр можно передать **только** как `c=значение`, не позиционно
4. Именованные со значением по умолчанию (`d=10`)
5. `**kwargs`

```python
func(1, 2, 3, 4, 5, c=100, extra="что-то")
# a=1, b=2, args=(3,4,5), c=100, d=10 (по умолчанию), kwargs={'extra': 'что-то'}
```

> [!warning] Нельзя поставить обычный параметр после `*args` и ожидать позиционной передачи
> Всё, что идёт после `*args` в определении функции, можно передать **только по имени**. Это не баг, а осознанное ограничение синтаксиса Python.

## Распаковка (`*`/`**`) при **вызове** функции — обратная операция

То же самое работает и в обратную сторону — распаковать существующую коллекцию в отдельные аргументы при вызове:

```python
def add(a, b, c):
    return a + b + c

numbers = [1, 2, 3]
add(*numbers)          # эквивалентно add(1, 2, 3) — list распаковывается в позиционные аргументы

params = {"a": 1, "b": 2, "c": 3}
add(**params)            # эквивалентно add(a=1, b=2, c=3) — dict распаковывается в именованные
```

Это **та же звёздочка**, что и в определении функции, но смысл противоположный: в определении — "собери в tuple/dict", при вызове — "разбери tuple/dict на отдельные аргументы". Не путай направление.

## Практическое применение — форвардинг аргументов

Самый частый сценарий использования `*args, **kwargs` вместе — функция-обёртка, которая сама не знает заранее, что ей передадут, и просто передаёт всё дальше в другую функцию:

```python
def logged_call(func, *args, **kwargs):
    print(f"Вызываю {func.__name__} с args={args}, kwargs={kwargs}")
    return func(*args, **kwargs)     # распаковка — передаём дальше как есть

def add(a, b):
    return a + b

logged_call(add, 2, 3)          # Вызываю add с args=(2, 3), kwargs={}
```

Это база того, как устроены декораторы (увидишь позже) и почему в ООП часто пишут `super().__init__(*args, **kwargs)` — передать все аргументы родительскому классу, не переписывая их по одному.

## Частые ошибки

> [!warning] Путать `*args` (tuple) и `**kwargs` (dict)
> `args[0]` — обращение по индексу (как к tuple). `kwargs["name"]` или `kwargs.get("name")` — обращение по ключу (как к dict). Перепутать структуру данных — частая причина `TypeError`/`KeyError` на пустом месте.

> [!danger] Пытаться передать именованный аргумент туда, где ожидается `*args`
> ```python
> def total(*args):
>     return sum(args)
> total(a=1, b=2)   # TypeError — *args не принимает именованные аргументы, для этого нужен **kwargs
> ```

> [!danger] Изменяемый объект как значение по умолчанию — не про args/kwargs напрямую, но встречается рядом
> ```python
> def add_item(item, items=[]):   # ОПАСНО — список создаётся ОДИН раз при определении функции
>     items.append(item)
>     return items
> ```
> Не тема этой заметки, но всплывает в том же контексте гибких функций — держи в голове на будущее, разберём отдельно, если понадобится.
