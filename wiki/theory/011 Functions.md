# Functions

> [!info] Что это
> Функция — именованный блок кода, который можно вызывать многократно.
>
> ```python
> def greet(name):
>     return f"Привет, {name}!"
>
> result = greet("Ваня")
> print(result)
> ```
>
> - `def` — объявление функции
> - `name` — параметр
> - `return` — возвращает значение и завершает функцию. Без `return` функция вернёт `None`

Причина, почему это важно, видна на твоём же коде: в [[Buy Manager]] было три одинаковых `int(input(menu_text))` в разных ветках `if`. Переменная `menu_text` убрала дублирование текста, но не дублирование *действия* — "показать меню и получить число от пользователя". Функция убирает и это.

---

## return vs print — ключевое различие

```python
def bad_add(a, b):
    print(a + b)     # результат "потерян" для остальной программы

def good_add(a, b):
    return a + b      # результат можно сохранить и использовать дальше
```

Реальные разработчики почти никогда не делают `print()` внутри функции, которая должна что-то вычислять — иначе функцию нельзя переиспользовать. Печать — дело вызывающего кода, не функции.

## Параметры и значения по умолчанию

```python
def power(base, exponent=2):
    return base ** exponent

power(5)        # 25
power(5, 3)      # 125
```

> [!danger] Ловушка: вызвать ≠ получить результат
> ```python
> def get_menu_choice():
>     return int(input(menu_text))
>
> get_menu_choice()   # ❌ вызвали, но результат никуда не дели
> ```
> `get_menu_choice()` честно вернул число через `return` — но оно исчезает, если не присвоить переменной:
> ```python
> user_answer = get_menu_choice()   # ✅ вот теперь результат сохранён
> ```
> `return` отдаёт значение «наружу», в точку вызова. Что с ним делать дальше — решает тот, кто вызвал, а не сама функция.

## 🏠 Область видимости (scope)

Переменная, созданная **внутри** функции — локальная. Она исчезает, как только функция завершилась:

```python
def show_balance():
    message = f'Ваш баланс: {balance}'
    print(message)

show_balance()
print(message)   # ❌ NameError: message не существует снаружи функции
```

Читать переменную, объявленную **снаружи** (глобальную), функция может:

```python
balance = 1000

def show_balance():
    print(balance)   # ✅ чтение глобальной переменной работает
```

> [!danger] Изменить глобальную через `=` внутри функции не получится
> ```python
> balance = 1000
>
> def add_money(amount):
>     balance = balance + amount   # ❌ UnboundLocalError
> ```
> Python видит, что `balance` присваивается внутри функции, и считает её локальной сразу, даже до строки, где присваивание происходит — поэтому падает при попытке прочитать её справа от `+`.

> [!tip] Правильный подход
> Функция не изменяет глобальное напрямую, а **принимает значение параметром и возвращает новое через `return`**:
> ```python
> def add_money(balance, amount):
>     return balance + amount
>
> balance = 1000
> balance = add_money(balance, 500)   # ✅ явно и предсказуемо
> ```
> Есть `global`, позволяющее менять глобальную переменную напрямую — в реальном коде почти не используется: функция начинает неявно менять что-то вне себя, это трудно отлаживать. Просто знай, что оно есть — не используй сейчас.

## 📦 Несколько значений из одной функции

```python
def get_min_max(numbers):
    return min(numbers), max(numbers)

low, high = get_min_max([4, 9, 1, 7])
print(low, high)   # 1 7
```

Технически функция возвращает один кортеж (`tuple`, ещё разберём отдельно) — но синтаксис уже полезен: функция валидации может вернуть и `результат`, и `сообщение об ошибке` одним вызовом.

## 🔗 Функции, вызывающие другие функции

```python
def is_valid_amount(amount, balance):
    return 0 < amount <= balance

def withdraw(balance, amount):
    if is_valid_amount(amount, balance):
        return balance - amount
    print('Недопустимая сумма')
    return balance
```

`withdraw` не дублирует логику проверки, а передаёт её отдельной, маленькой функции. Это архитектура на уровне функций: каждая делает одну вещь и делает её хорошо.

## Docstring — описание функции

```python
def withdraw(balance, amount):
    """Списывает amount с balance, если средств достаточно."""
    ...
```

Строка сразу после `def` в тройных кавычках — описание, что функция делает. В реальных проектах пишется почти к каждой функции сложнее одной строки.

## *args и **kwargs (обзорно)

```python
def total(*numbers):
    return sum(numbers)

total(1, 2, 3, 4)   # работает с любым количеством аргументов
```

`**kwargs` — то же самое, но для именованных аргументов (собираются в словарь). Пока достаточно узнавать эту запись в чужом коде.

## Частые ошибки

> [!warning] Изменяемый объект как значение по умолчанию
> ```python
> def bad(items=[]):   # НЕЛЬЗЯ — список общий для всех вызовов функции
>     items.append(1)
>     return items
> ```

> [!warning] print() вместо return
> Если функция вычисляет что-то, результат должен уходить через `return`, а не сразу печататься.
