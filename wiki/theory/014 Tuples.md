# Tuples (кортежи)

> [!info] Что это
> Кортеж — упорядоченная коллекция, как список, но **неизменяемая (immutable)**. Один раз создал — нельзя добавить элемент, удалить или изменить по индексу. Синтаксис — круглые скобки.
>
> ```python
> point = (10, 20)
> point[0] = 5   # TypeError: 'tuple' object does not support item assignment
> ```

---

## Как создать кортеж — тонкости синтаксиса

```python
empty = ()                 # пустой кортеж
single = (5,)               # кортеж из ОДНОГО элемента — запятая обязательна
not_a_tuple = (5)            # это НЕ кортеж, это просто число 5 в скобках
without_parens = 5, 10, 15    # тоже кортеж! Скобки не обязательны, важна запятая
```

> [!danger] Кортеж из одного элемента без запятой
> `x = (5)` → `type(x)` это `int`, не `tuple`. Python использует круглые скобки и для группировки выражений (`(2 + 3) * 4`), поэтому именно **запятая**, а не скобки, определяет кортеж. `(5,)` — кортеж, `(5)` — число.

---

## Что можно делать с кортежем — операции, унаследованные от последовательностей

Все "read-only" операции списка работают одинаково:

```python
point = (10, 20, 30)
point[0]           # 10 — индексация работает
point[-1]           # 30 — отрицательные индексы работают
point[0:2]           # (10, 20) — срез тоже кортеж, а не список
len(point)            # 3
10 in point            # True
for x in point:         # итерация работает
    print(x)
point.count(10)          # 1 — сколько раз встречается значение
point.index(20)           # 1 — индекс первого вхождения
```

Не работает: `.append()`, `.remove()`, `.insert()`, `.sort()`, `point[0] = 5` — всё, что **меняет** коллекцию. `sorted(point)` при этом работает и вернёт **новый список** (не кортеж) — сортировка не меняет исходный объект, а создаёт новый.

## Зачем нужен отдельный неизменяемый тип

> [!tip] Правило
> Используй tuple, когда данные **логически фиксированы** и не должны меняться в течение жизни программы — RGB-цвет `(255, 0, 0)`, координата `(x, y)`, дата `(2026, 7, 17)`, запись `(имя, счёт)`. Неизменяемость — это не ограничение, а **гарантия**: любой, кто читает код, сразу понимает намерение — "эту структуру нельзя редактировать на месте, только заменить целиком".

Есть и техническая причина: неизменяемые объекты можно использовать как **ключи словаря** и **элементы set**, а списки — нельзя:

```python
locations = {}
locations[(55.75, 37.61)] = "Москва"   # tuple как ключ — работает

locations[[55.75, 37.61]] = "Москва"    # TypeError: unhashable type: 'list'
```

Это прямое следствие того же принципа, что вызывал у тебя `TypeError: unhashable type: 'list'` в разборе бага в `Expense Tracker` — только тогда это было ошибкой, а здесь это осознанное применение того же правила: изменяемые типы нельзя хэшировать, поэтому их нельзя использовать как ключи.

## Множественный return — самое частое практическое применение

Функция может вернуть сразу несколько значений — синтаксически это создание tuple без явных скобок:

```python
def get_min_max(numbers):
    return min(numbers), max(numbers)   # на деле: return (min(numbers), max(numbers))

result = get_min_max([5, 2, 9, 1])
print(result)          # (1, 9) — это tuple
print(type(result))     # <class 'tuple'>
```

### Unpacking — распаковка в отдельные переменные

```python
low, high = get_min_max([5, 2, 9, 1])
print(low, high)   # 1 9
```

Количество переменных слева должно совпадать с количеством элементов в кортеже — иначе `ValueError: too many values to unpack` (или наоборот, `not enough values to unpack`).

### Unpacking с `*` — когда количество элементов заранее неизвестно

```python
first, *rest = (1, 2, 3, 4)
print(first)   # 1
print(rest)     # [2, 3, 4] — обрати внимание, это list, не tuple

*rest, last = (1, 2, 3, 4)
print(rest, last)   # [1, 2, 3] 4
```

### Swap без временной переменной — идиома, основанная на tuple

```python
a, b = 1, 2
a, b = b, a    # под капотом: создаётся tuple (b, a), затем распаковывается в a, b
print(a, b)     # 2 1
```

## Частые ошибки

> [!warning] Кортеж из одного элемента без запятой
> Уже разобрано выше — самая частая ошибка новичков с tuple.

> [!danger] Попытка "обновить" кортеж внутри функции
> Если кажется, что нужно изменить элемент tuple — тебе либо нужен list (если коллекция правда должна меняться), либо нужно создать **новый** tuple и вернуть его через `return`, заменив старый целиком, а не мутировать существующий:
> ```python
> point = (10, 20)
> point = (point[0] + 5, point[1])   # не изменение, а замена на новый tuple
> ```

> [!danger] Кортеж, содержащий изменяемый объект внутри
> ```python
> t = (1, 2, [3, 4])
> t[2].append(5)   # это РАБОТАЕТ! t теперь (1, 2, [3, 4, 5])
> t[2] = [3, 4, 5]  # а вот это упадёт — TypeError
> ```
> Неизменяемость tuple касается только **самого кортежа как контейнера** — нельзя менять, какие объекты в нём лежат. Но если один из объектов внутри — изменяемый (например, список), его содержимое менять можно. Это тонкий момент, который стоит просто знать, чтобы не удивляться.
