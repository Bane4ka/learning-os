# Sorting Algorithms (алгоритмы сортировки)

> [!info] Что это
> Сортировка — расстановка элементов коллекции в определённом порядке (по возрастанию/убыванию). Кажется тривиальной задачей (в Python есть `sorted()`), но именно на сортировке лучше всего видно, как **разные алгоритмы решают одну и ту же задачу с разной сложностью** — прямое продолжение [[016 Big O]]. Плюс сортировка — обязательное условие для [[Search Algorithms]]: бинарный поиск не работает на неотсортированных данных.

---

## Наивные сортировки — O(n²), но с ними стоит начать

### Bubble Sort (пузырьковая сортировка)

Идея: пройтись по списку, сравнивая соседние элементы, и менять их местами, если они в неправильном порядке. Повторять проходы, пока за весь проход не случится ни одного обмена — значит, список отсортирован.

```
[5, 3, 8, 1]
проход 1: сравнить (5,3)→поменять→[3,5,8,1]; (5,8)→ок; (8,1)→поменять→[3,5,1,8]
проход 2: (3,5)→ок; (5,1)→поменять→[3,1,5,8]; (5,8)→ок
проход 3: (3,1)→поменять→[1,3,5,8]; (3,5)→ок
проход 4: ни одного обмена → готово
```

- **Худший/средний случай**: `O(n²)` — вложенный проход по всему списку для каждого элемента
- **Лучший случай**: `O(n)` — если список уже отсортирован и добавить проверку "не было обменов → выйти раньше" (без этой оптимизации даже отсортированный список даст `O(n²)`)
- **Память**: `O(1)` — сортирует "на месте" (in-place), не создаёт копию

### Selection Sort (сортировка выбором)

Идея: найти минимальный элемент во всём непросмотренном "хвосте" списка, поставить его в начало этого хвоста. Повторить для оставшегося хвоста.

```
[5, 3, 8, 1]
найти min в [5,3,8,1] → 1, поменять с первым → [1,3,8,5]
найти min в [3,8,5] (без первого) → 3, уже на месте → [1,3,8,5]
найти min в [8,5] → 5, поменять → [1,3,5,8]
готово
```

- **Всегда** `O(n²)`, даже на уже отсортированном списке — нет способа выйти раньше, поиск минимума всегда полный
- **Память**: `O(1)`
- Плюс перед Bubble Sort: делает не более `n` обменов (Bubble Sort может делать намного больше) — полезно, если сама операция обмена дорогая (например, обмен больших объектов, а не чисел)

### Insertion Sort (сортировка вставками)

Идея: строить отсортированную часть слева направо, каждый следующий элемент "вставлять" в уже отсортированную часть на правильную позицию — как раскладывают карты в руке.

```
[5, 3, 8, 1]
[5] | 3 → вставить перед 5 → [3,5]
[3,5] | 8 → вставить после 5 → [3,5,8]
[3,5,8] | 1 → вставить в начало → [1,3,5,8]
```

- **Худший случай**: `O(n²)` — если список отсортирован в обратном порядке
- **Лучший случай**: `O(n)` — если список **уже почти отсортирован**, каждый элемент почти не двигается. Это единственная из трёх наивных сортировок, которая реально быстро отрабатывает на "почти готовых" данных
- **Память**: `O(1)`
- Практическое применение: используется как часть более сложных алгоритмов (в том числе внутри Python'овского Timsort) именно из-за эффективности на маленьких/почти отсортированных участках

## Divide and Conquer (разделяй и властвуй) — переход к эффективным сортировкам

Это парадигма, а не конкретный алгоритм: разбить задачу на подзадачи меньшего размера, решить их (часто рекурсивно), объединить результаты. И Merge Sort, и Quick Sort — представители этого подхода, оба используют рекурсию из [[Search Algorithms]].

### Merge Sort (сортировка слиянием)

Идея: разбить список пополам, рекурсивно отсортировать каждую половину, затем **слить** две отсортированные половины в одну.

```
[5, 3, 8, 1]
разбить → [5, 3] и [8, 1]
разбить дальше → [5],[3] и [8],[1]  ← base case: список из 1 элемента уже "отсортирован"
слить [5] и [3] → [3, 5]
слить [8] и [1] → [1, 8]
слить [3, 5] и [1, 8] → [1, 3, 5, 8]
```

Шаг "слияния" (merge) — ключевая операция: два уже отсортированных списка можно слить в один отсортированный за один проход, сравнивая головы каждого списка.

- **Всегда** `O(n log n)` — и в худшем, и в среднем, и в лучшем случае. `log n` — количество уровней разбиения пополам (см. [[016 Big O]], рекуррентное соотношение `T(n) = 2T(n/2) + O(n)`)
- **Память**: `O(n)` — требует дополнительный массив для слияния, **не** in-place
- **Стабильность**: стабильный (см. ниже)

### Quick Sort (быстрая сортировка)

Идея: выбрать **опорный элемент (pivot)**, разбить список на "меньше pivot" и "больше pivot", рекурсивно отсортировать обе части, объединить (тут объединение тривиально — части уже на своих местах).

```
[5, 3, 8, 1], pivot = 5 (например, последний элемент)
меньше 5: [3, 1]   больше 5: [8]
рекурсивно сортируем [3,1] → [1,3], и [8] → [8]
результат: [1, 3] + [5] + [8] = [1, 3, 5, 8]
```

- **Средний случай**: `O(n log n)` — при удачном выборе pivot части делятся примерно пополам
- **Худший случай**: `O(n²)` — если pivot **каждый раз** оказывается минимумом или максимумом (например, всегда брать первый элемент на **уже отсортированном** списке — классическая ловушка)
- **Память**: `O(log n)` на стек рекурсии — в среднем эффективнее Merge Sort по памяти, работает in-place на самих данных
- **Стабильность**: нестабильный (см. ниже)

> [!tip] Почему на практике Quick Sort часто быстрее Merge Sort, хотя оба "O(n log n)"
> Big O скрывает константы. Quick Sort обычно имеет меньшую константу (меньше операций копирования памяти, работает in-place), поэтому на практике быстрее при **среднем** случае, даже при одинаковом классе сложности. Это ровно та ситуация из предупреждения в [[016 Big O]] — "не путай Big O с реальным временем в секундах".

## Стабильность сортировки — что это и почему важно

Сортировка **стабильна**, если элементы с одинаковым ключом сортировки сохраняют свой изначальный относительный порядок.

```python
students = [("Аня", 90), ("Ваня", 85), ("Петя", 90)]
# сортируем по очкам (второй элемент)
```

Если сортировка стабильна — при одинаковых очках (90 у Ани и Пети) Аня останется перед Петей, потому что была перед ним изначально. Нестабильная сортировка может поменять их местами без причины, видимой в данных.

**Когда это критично**: сортировка в несколько этапов. Например, сначала отсортировал список сотрудников по имени, потом по отделу — если вторая сортировка стабильна, внутри каждого отдела люди останутся отсортированы по имени. Если нестабильна — этот порядок может потеряться.

| Алгоритм | Стабильный? |
|---|---|
| Bubble Sort | Да |
| Insertion Sort | Да |
| Selection Sort | Нет (классическая реализация) |
| Merge Sort | Да |
| Quick Sort | Нет (классическая реализация) |

## Сравнительная таблица — держи под рукой

| Алгоритм | Best | Average | Worst | Память | Стабилен |
|---|---|---|---|---|---|
| Bubble Sort | O(n) с оптимизацией | O(n²) | O(n²) | O(1) | Да |
| Selection Sort | O(n²) | O(n²) | O(n²) | O(1) | Нет |
| Insertion Sort | O(n) | O(n²) | O(n²) | O(1) | Да |
| Merge Sort | O(n log n) | O(n log n) | O(n log n) | O(n) | Да |
| Quick Sort | O(n log n) | O(n log n) | O(n²) | O(log n) | Нет |

## А что реально использовать в коде — `sorted()` / `.sort()`

```python
sorted(my_list)          # возвращает НОВЫЙ отсортированный список, оригинал не трогает
my_list.sort()             # сортирует НА МЕСТЕ, возвращает None (частая ошибка — x = my_list.sort())
sorted(my_list, key=lambda x: x[1])   # сортировка по второму элементу кортежа — то, что нужно для Quiz Leaderboard
sorted(my_list, reverse=True)          # по убыванию
```

Python использует **Timsort** — гибрид Merge Sort и Insertion Sort, `O(n log n)` в худшем случае, стабильный, оптимизирован под реальные данные (умеет находить уже отсортированные участки и не пересортировывать их зря). В продакшн-коде ты почти никогда не пишешь сортировку руками — но понимание того, что происходит внутри, объясняет, почему `sorted()` стабилен и почему это не случайность.

> [!warning] `list.sort()` возвращает `None`
> ```python
> result = my_list.sort()
> print(result)   # None! Список отсортировался, но метод ничего не вернул
> ```
> Частая ошибка — путать `.sort()` (мутирует, возвращает `None`) и `sorted()` (не мутирует, возвращает новый список).

## Частые ошибки при реализации руками

> [!danger] Off-by-one в границах цикла
> Особенно в Bubble Sort — легко пройти на один индекс дальше и получить `IndexError`, либо на один меньше и не сравнить последнюю пару.

> [!danger] Забытый base case в рекурсивном Merge/Quick Sort
> Без условия "список из 0 или 1 элемента уже отсортирован" — бесконечная рекурсия, `RecursionError`. Та же логика, что ты уже проходил в `binary_search_recursive`.

> [!danger] Плохой выбор pivot в Quick Sort
> Если всегда брать первый (или последний) элемент как pivot, а входные данные уже отсортированы (или отсортированы в обратном порядке) — Quick Sort деградирует до `O(n²)`, худший сценарий на самых обычных на вид данных. На практике используют случайный выбор pivot или медиану трёх, чтобы этого избежать.
